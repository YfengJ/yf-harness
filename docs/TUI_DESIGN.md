# TUI 设计

Textual 界面使用三栏：左侧会话，中间 Markdown 对话与多行输入，右侧运行状态和上下文。工具调用以可折叠卡片展示，审批使用 ModalScreen 显示风险、参数、路径、命令和 Diff。窄终端动态隐藏侧栏并给出提示，而非依赖框架不支持的静态媒体查询。

组件层次是 `HarnessApp` → Header/三栏容器/Input/Footer，并按需压入 Approval、Settings、Help Screen。App 持有可展示状态，Session/Agent/Repository 保持业务事实；状态更新统一回到 Textual 消息循环。

UI 只订阅 Agent 事件并派发用户意图，不自行实现 Provider、策略或工具。流式输出持续更新当前消息；用户向上滚动时暂停自动跟随。`Ctrl+C` 取消当前运行，不退出应用。Slash Command 在客户端解析，命令补全和输入历史不发送给模型。

Provider、数据库和工具都运行在异步任务中；同步阻塞工作必须下放线程或子进程，不能占用 UI 主线程，否则输入、绘制与取消都会冻结。后台任务也不能跨线程直接修改 Widget，而应发送事件回到 App。

无障碍原则包括键盘可达、文字状态不只依赖颜色、清晰焦点、Modal 可返回、错误可恢复。Headless pilot 测试覆盖真实 Mock 流、快捷键、Modal 和响应式尺寸。

## 我应该理解什么

TUI 是核心状态的投影；业务规则不能只存在于界面事件里。

## 我可以修改什么来做实验

调整工具卡默认折叠规则，使用 headless 测试比较长输出体验。

## 常见 Bug

后台任务直接改 Widget、自动滚动抢用户位置、全局 Esc 吞掉 Modal、窄屏溢出。

## 面试可能如何提问

如何把异步流映射到终端 UI？取消和背压如何处理？

## 一个动手练习

增加显示本轮工具计数的状态字段，并写一个 pilot 测试。
