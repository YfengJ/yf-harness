# 架构决策记录

## ADR-009：桌面主界面采用 Qt Quick，TUI 保留兼容

状态：接受。PySide6 + Qt Quick 提供真正独立的桌面窗口和 macOS App Bundle，Python Bridge 复用现有
AgentRunner 与 Repository。Qt 只放在 `desktop` extra 中，默认 CLI wheel 不强制安装大型 GUI 运行时。

替代方案：继续把 Textual TUI 当主界面；拒绝，因为它始终运行在终端。浏览器/Electron 壳也被拒绝，
因为当前本地 Python 核心无需额外服务进程。代价是自包含 Qt App 体积较大，正式公开分发还需平台签名与公证。

## ADR-001：核心不采用高级 Agent 框架，可选边界允许原生集成

状态：修订后接受。核心继续直接实现事件、循环和策略，使边界可学习、可测试、供应商中立；
LangChain、LlamaIndex、AutoGen 只作为 optional extras 和边缘适配器。代价是需要维护版本化映射与契约测试。

替代方案：让任一框架取代 AgentRunner；拒绝，因为会遮蔽核心机制并可能绕过统一审批。另一个方案是
完全不集成生态框架；拒绝，因为用户无法复用框架 Agent API。适配层首版不注入本地工具，远程调用使用
框架官方 OpenAI-compatible 客户端，离线调用也必须经过框架原生 Agent 对象。

## ADR-008：框架依赖按 extra 隔离并惰性导入

状态：接受。`langchain`、`llamaindex`、`autogen` 可单独安装，`frameworks` 聚合安装全部；默认 wheel
的运行依赖不增加大型 SDK。发现与 Doctor 只读取 distribution metadata，选择运行后才导入对应模块。

替代方案：把三套框架列为必装依赖；拒绝，因为会显著增加默认解析、下载和冲突面。运行时静默回退到
YF-Harness Mock 也被拒绝，因为会制造“看似使用框架”的假集成；缺包时必须给出明确安装命令并失败。

## ADR-002：统一事件是 Provider 唯一输出

状态：接受。隔离 API 差异并让 CLI/TUI/Trace 复用；代价是新供应商字段必须显式映射或舍弃。

替代方案：各界面直接消费供应商响应；拒绝，因为会把变化扩散到整个系统。

## ADR-003：SQLite 只经 Repository

状态：接受。集中迁移、事务与序列化；代价是简单查询也需接口。

替代方案：调用点直接写 SQL 或使用完整 ORM；前者边界失控，后者对首版本地 schema 过重。

## ADR-004：四模式共享 AgentRunner

状态：接受。差异由策略表达，防止四份循环漂移；代价是策略组合必须严谨测试。

替代方案：每种模式独立 Runner；拒绝，因为取消、预算和修复语义容易分叉。

## ADR-005：默认 Mock、默认拒绝 full_auto

状态：接受。克隆后无需 Key 即可验证，危险能力不因配置遗漏开启；代价是首次真实使用需明确配置。

替代方案：默认真实 Provider 或自动执行；拒绝，因为不可复现且默认风险过高。

## ADR-006：降级协议使用严格 JSON

状态：接受。避免从自然语言猜测执行意图；代价是能力较弱模型可能需要有限修复轮。

替代方案：正则抽取或 Markdown 代码块；拒绝，因为文本与执行意图边界含糊。

## ADR-007：本地优先但不宣称强沙箱

状态：接受。workspace、审批和进程限制降低风险，同时诚实记录 OS 隔离缺失。

替代方案：内置容器强制执行或不做任何隔离；前者破坏跨平台最小体验，后者不可接受。
