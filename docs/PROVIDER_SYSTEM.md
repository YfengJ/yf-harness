# Provider 系统

Provider 接收规范化消息、模型配置、工具 Schema 和取消上下文，异步产出 `ModelEvent`。事件类型覆盖文本增量、推理增量、工具调用片段/完成、用量、完成与错误；核心不解析供应商私有对象。

`MockProvider` 是默认实现，用于无 Key 体验、确定性测试、脚本化工具与错误注入。`OpenAICompatibleProvider` 直接使用 httpx：支持 JSON 和 SSE，按响应状态归一化鉴权、限流、超时、网络和协议错误。重试采用有限退避，仅发生在任何事件交付之前。推理字段必须由配置显式启用。

能力差异由模型配置声明，包括是否流式、是否原生工具、上下文窗口和可选推理输出。Harness 据此选择原生或降级协议，但始终保持同一事件与 Agent 语义；不支持的能力应清晰降级或报错，不能静默猜测。

注册表按配置中的 `type` 创建实例。模型能力、上下文长度和价格属于用户配置，不能根据名字猜测。API Key 通过环境变量名延迟读取，禁止进入序列化配置。

新增 Provider 时先映射成统一事件，明确流终止、用量缺失、工具参数分片、取消和错误语义，并用本地假 HTTP/脚本测试。

## 我应该理解什么

Provider 是传输适配层，不是 Agent；统一事件是唯一公共输出。

## 我可以修改什么来做实验

给 MockProvider 增加一个分片模式，验证 UI 不依赖分片边界。

## 常见 Bug

按单行假设 SSE、重复拼接工具参数、在日志中记录认证头、依据模型名猜能力。

## 面试可能如何提问

如何兼容多家流式 API？如何处理流式请求的重试与幂等？

## 一个动手练习

实现一个仅支持非流式响应的测试 Provider，并让同一 CLI 用例通过。
