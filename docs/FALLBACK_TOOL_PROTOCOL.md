# JSON 降级工具协议

当模型不支持原生 Tool Calling 时，Harness 要求回答只能是普通最终文本，或一个严格 JSON 对象：

```json
{"tool_calls":[{"id":"call_1","name":"read_file","arguments":{"path":"README.md"}}]}
```

根对象只允许 `tool_calls`，调用只允许 `id`、`name`、`arguments`；禁止 Markdown 围栏、前后解释、未知字段和非对象参数。解析后仍经过与原生调用完全相同的注册表、Pydantic Schema、策略、审批及安全检查。协议错误可获得有限的模型修复机会，不能无限重试。

该协议只是传输替代，不是权限捷径。看起来像 JSON 的普通文本只有满足完整严格结构时才会被解释为调用；工具结果以带角色和调用 ID 的消息回填。

## 我应该理解什么

降级协议只解决表达工具调用，不解决验证、授权或执行安全。

## 我可以修改什么来做实验

输入带代码围栏、额外字段或数组根节点的样例，观察错误归一化。

## 常见 Bug

用正则抽取任意 JSON、接受尾随文本、跳过 Schema、修复次数无上限。

## 面试可能如何提问

没有原生函数调用时如何设计可靠协议？严格解析的价值是什么？

## 一个动手练习

为重复调用 ID 添加一个拒绝测试，并给出清晰修复提示。
